# Morning Note

## 目标

在 2 分钟内可读完的一页晨会材料中，回答三个问题：

1. 隔夜到开盘前最重要的新增信息是什么？
2. 它对 A 股/港股/覆盖标的的交易含义是什么？
3. 今天交易员、基金经理、研究员应重点盯什么？

## Workflow

### Step 1: 确定覆盖范围和时间口径

- 默认时间口径：上一交易日 A 股收盘后至今日 A 股开盘前。
- 如用户指定行业、股票池或主题，优先围绕该范围；否则覆盖全市场重大事件和高相关板块。
- 在正文开头注明日期和撰写时点，例如“截至北京时间 08:10”。

### Step 2: 扫描隔夜市场

优先使用 iFind：

- 美股三大指数、纳斯达克、费城半导体、重点行业 ETF。
- 港股 ADR、中概股、重点 A/H 或 A/ADR 映射标的。
- 商品：原油、铜、黄金、锂、煤炭、钢材等与主题相关品种。
- 汇率/利率：离岸人民币、美元指数、美债收益率。
- 宏观数据和海外政策事件，判断其对中国资产风险偏好的影响。

输出要求：

- 不只罗列涨跌幅，要写“对 A 股开盘情绪的含义”。
- 数值必须带来源；口径不明或无法验证，标 `[UNSOURCED]`。

### Step 3: 扫描政策、监管和交易所公告

重点来源：

- 国务院、部委、央行、证监会、交易所、地方政府。
- 行业监管文件、征求意见稿、处罚、窗口指导、交易规则变化。
- 交易所问询、停复牌、重大资产重组、退市风险、减持规则相关公告。

判断框架：

- 影响方向：利好/利空/中性/待观察。
- 影响链条：政策 -> 行业供需/价格/成本/准入 -> 公司盈利/估值/风险偏好。
- 可交易性：今日是否可能直接驱动板块或个股。

### Step 4: 扫描公司公告和业绩事件

覆盖：

- 业绩快报、业绩预告、正式财报、盈利修正、分红回购。
- 并购重组、定增、股权激励、重大合同、订单、产能投放、诉讼处罚。
- 股东减持/增持、质押、限售解禁、停复牌。
- 机构调研要点、投资者关系活动记录。

快速反应模板：

| 项目 | 市场预期/历史口径 | 公告/实际 | 判断 |
| --- | --- | --- | --- |
| 收入/利润/关键指标 |  |  | Beat/Miss/Inline |
| 指引/订单/价格 |  |  |  |
| 风险点 |  |  |  |

随后用 2-3 句写清：

- 是否改变原有投资 thesis。
- 对今日股价、板块映射、估值或仓位的影响。
- 需要进一步核实的数据。

### Step 5: 资金面和交易线索

可选但建议覆盖：

- 北向资金、南向资金、ETF 申赎和成交活跃产品。
- 龙虎榜、机构席位、游资席位、融资融券变化。
- 股指期货基差、持仓、期权波动率。
- 解禁、打新、再融资、可转债等供给因素。

注意：

- 资金数据不能替代基本面判断，只能作为开盘情绪和交易拥挤度的辅助证据。
- 异常资金流需要结合新闻、公告、估值和技术位置解释。

### Step 6: 写 Morning Note

建议格式：

```markdown
# YYYY-MM-DD A股开盘前 Morning Note

**Top Call:** [一句话，必须可交易或可决策]

## 隔夜市场与开盘情绪
- [事实 + 影响判断 + 来源]

## 政策/监管/宏观
- [事件 + 影响链条 + 来源]

## 公司公告与行业事件
- [代码 公司]: [事件]；[我们的判断] [来源]

## 资金面与交易线索
- [资金/期指/龙虎榜/ETF]；[解释]

## 今日关注
- [时间] [事项]：[看点]

## Trade Ideas
- [多/空/观望] [标的/板块]：[催化剂 + thesis]
- Risk：[反向风险]

## 来源与未来源化信息
- [主要来源列表]
- [UNSOURCED] [如有]
```

### Step 7: 保存产物

- 禁止调用或请求 `general-purpose` subagent；本 agent 不应使用任何通用委派 subagent。需要补充信息时，使用已配置的 MCP/本地工具完成，或在最终回复中说明缺口。
- 调用 `create_task_output_dir` 创建输出目录。
- Finalization / 落盘顺序：MCP、搜索和研究工具可以使用，但必须在任何 `write_*` 文件写入前全部完成。隔夜市场、政策监管、公司事件、资金面、今日日程和来源核验都完成并定稿后，再一次性写 JSON artifact 和最终 `morning-note.md`。
- 写 Markdown、JSON 等业务产物视为 finalization 阶段；一旦 `write_markdown_report` 或 `write_json_artifact` 成功，不要再启动补查资料、调用 MCP/搜索或继续研究。只允许写完同一批已定稿产物，然后直接返回路径与限制说明。
- 如果写完后才发现信息缺口，不要继续研究后改文件；在 final response 中说明缺口或建议重新运行。
- 调用 `write_markdown_report` 写入最终 Markdown。
- 如有结构化资料，调用 `write_json_artifact` 写入：
  - `source-log.json`
  - `company-events.json`
  - `today-calendar.json`
  - `market-snapshot.json`

## Important Notes

- 观点要前置。Morning Note 不是新闻合集。
- 宁可少写，也不要写无法验证的精确数字。
- 对 `[UNSOURCED]` 保持透明，不能混在有来源事实里。
- A 股开盘前材料必须照顾交易时效，优先选择今天可能影响价格的内容。
- “无重大新增”是有效结论，但要说明检查过哪些模块。
- 如果用户要求正式分发，保持一页以内、标题清晰、bullet 紧凑。
